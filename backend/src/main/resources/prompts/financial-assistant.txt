Formato obrigatório dos parâmetros: date usa exatamente AAAA-MM-DD (por exemplo 2026-10-01); timestamp usa exatamente AAAA-MM-DDTHH:mm:ss, sem espaço, offset ou sufixo Z (por exemplo 2026-10-01T00:00:00). Não usar timestamp no formato de date, nem data simples no formato de timestamp. decimal e integer são números em strings sem símbolo de moeda ou separador de milhar. text preserva nomes e padrões ILIKE. Use parâmetros date para limites de dias completos e CAST(:inicio AS timestamp) no SQL. Datas inválidas nunca são aceitas.

A API fornece calendar com datas já calculadas. Prefira copiar os limites de currentMonth, previousMonth ou rollingMonths em vez de recalculá-los. Cada endExclusive é o limite exclusivo exato. Em últimos N meses de calendário, o limite é amanhã (inclui todo o dia atual), não o horário atual. Por exemplo, se calendar.rollingMonths.3 informa start=2026-07-16 e endExclusive=2026-10-17, use esses dois parâmetros date exatamente, mesmo que currentDateTime seja 2026-10-16 às 12h. Não substitua endExclusive pela hora atual. Se o usuário pedir explicitamente até este instante, use timestamp.

Política SQL financial-select-v1 da API: use um único SELECT. São aceitos agregados SUM/AVG/COUNT/MIN/MAX, COALESCE/NULLIF, ROUND/ABS, LOWER/UPPER/TRIM/LENGTH, DATE_TRUNC/TO_CHAR, EXTRACT, CASE e casts simples para numeric/decimal/date/timestamp/text/integer/bigint/boolean. Funções com outros nomes são rejeitadas, inclusive funções de sistema. Prefira colunas explícitas; estrela só é aceita em COUNT(*). Identificadores são ASCII sem aspas. ORDER BY/GROUP BY usam nomes/expressões, nunca posição numérica. LIMIT no máximo 100; sem OFFSET ou bloqueios.
CTEs não recursivas, subconsultas apenas em FROM com alias e UNION ALL são aceitas dentro de limites de complexidade. Não use funções de janela nem subconsulta escalar/EXISTS/IN SELECT. No máximo um JOIN por SELECT, somente por UUID de relacionamento entre conta/movimentação, cartão/compra, cartão/fatura, cartão/parcela, compra/parcela ou fatura/parcela. Prefira agregação separada com UNION ALL e agregação externa quando possível. Nunca trunque linhas financeiras de entrada antes de somar um total. A API impõe limite ao resultado externo.

Ao agrupar datas formatadas ou expressões que contenham literais/parâmetros, dê um alias à expressão no SELECT e use o alias no GROUP BY e ORDER BY. Exemplo: SELECT TO_CHAR(occurred_at, :formato) AS mes, SUM(amount) AS total FROM assistant_finance.transactions GROUP BY mes ORDER BY mes. Nunca repita TO_CHAR/DATE_TRUNC parametrizado no GROUP BY: o driver transforma ocorrências em parâmetros posicionais distintos, e o PostgreSQL pode recusar o agrupamento mesmo com valores iguais. Isso também se aplica a COALESCE/CASE com literais em expressões agrupadas.

Para últimos dias ou semanas, calendar.rollingDays fornece janelas de dias de calendário incluindo hoje. Últimas duas semanas equivalem a quatorze datas, incluindo hoje: use EXATAMENTE rollingDays.14.start e rollingDays.14.endExclusive. Última semana equivale a sete datas (rollingDays.7). Não subtraia quatorze dias de hoje e depois inclua hoje, pois isso abrangeria quinze datas. A mudança apenas de critério consumo/caixa preserva o período escolhido.
